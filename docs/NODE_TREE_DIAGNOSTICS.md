# 小红书界面树排查

日期：2026-10-19。设备：24129PN74C，Android 17 / API 37，arm64-v8a，USB ADB，Root 后端；小红书包名 `com.xingin.xhs`，运行在本应用持有的虚拟显示 39。

本次通过受鉴权的 MCP HTTP 接口初始化临时客户端、正常申请租约，并读取当前页面。没有接管其他客户端、重建显示、重启小红书或更改无障碍授权。

## 实机结果

无障碍服务已启用并绑定。用户提供的历史调用记录中，`mode=tree, format=compact` 返回 `node_count=172`、`returned_node_count=49`；标签文字、信息流笔记和边界均在节点列表中。随后同页的 `mode=both` 也返回了相同的 49 个节点。该记录没有空树响应。

本次实机开始时，小红书有“星标关注上线了”介绍弹窗，完整树返回 12 个节点，精简树返回 3 个节点；节点可见性和包名正确。依据新观察中的节点 ID 点击该弹窗的关闭入口一次，输入被接受，但即时后续观察失败。等待 800ms 后重新观察，小红书主页面完整树返回 220 个节点，精简树返回 41 个节点；`truncated=false`，无 `nodes_error`。完整树中有 87 个可见节点、44 个带文字节点；精简输出中有 18 个带文字节点、27 个可点击节点。

主页面保持不变时，逐项核对调用参数：

| 参数 | 截图数量 | 是否含 nodes | 采集总数 / 输出节点数 |
| --- | --- | --- | --- |
| 省略 mode 和 include_nodes | 1 | 否 | 不采集 |
| mode=tree | 0 | 是 | 220 / 41 |
| mode=both | 1 | 是 | 220 / 41 |
| include_nodes=true | 1 | 是 | 220 / 41 |

完成后释放临时租约并删除临时 MCP 会话与 ADB 端口转发。没有对信息流内容执行点赞、关注、发布或文字输入。

## 结论和限制

用户提供的历史参数与返回表明原观察确实读到了 49 个节点；本次实测也未复现空树。省略观察模式会只获取截图，与 `nodes=[]` 不同；弹窗关闭瞬间则需要重新观察。历史记录还显示点击“关注”后图像未变化，输入状态为 `accepted/unconfirmed`；这是输入效果没有得到确认，不能据此判断界面树为空，也不能确认坐标点击生效。点击原因需要对应原截图的标签选中状态和页面状态，当前证据不足以确定。没有修改采集、可见性过滤、鉴权或租约逻辑，也不以当前页面结果推断小红书所有页面都可读取。
