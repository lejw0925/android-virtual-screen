# 后台运行权限改为可选 · 模拟器验收

验证日期：2026-10-30。设备：Android 14 模拟器（AVS_High，arm64-v8a，8 核 / 6 GB，host GPU），全新安装 debug 包并清空应用数据。

## 变更

- `missingMcpPermissions` 不再检查电池优化豁免，只保留 Root / Shizuku / Stellar 授权、通知、画中画三项必需权限。
- 后台运行改为可选入口：设置 → MCP 连接 → 「后台运行（可选）」显示当前状态并可跳转系统设置；首页、引导页、设置页共用同一逻辑。
- 首次开启 MCP 后，若仍未豁免电池优化，弹一次非阻塞提示「后台运行（可选）」，说明不授权也能完成首次检查和连接；确认后不再提示。原三秒倒计时确认弹窗移除。

## 验收步骤与结果

| 步骤 | 结果 |
| --- | --- |
| 电池优化状态 | `cmd deviceidle whitelist` 无本应用记录，确认「后台运行」未授权 |
| 首次运行 → 准备访问权限 | 引导页正常显示；模拟器自带 `su` 仅允许 root/shell，Root 后端无法授权，改用 Shizuku（`shizuku_server` 启动后授权「始终允许」） |
| 首次运行 → 连接你的 Agent → 开启 MCP | 未出现「开启 MCP 前需要授权」，MCP 直接启动，显示「MCP 已就绪」 |
| 可选提示 | 启动后弹出「后台运行（可选）」，文案说明不授权不影响首次检查与连接；按钮为「知道了 / 后台运行设置」 |
| 完成设置 | 引导正常结束，首页显示「MCP 服务 · 运行中」 |
| 服务可达性 | `adb forward` 后访问 `http://127.0.0.1:8732/` 返回 200；前台服务 `isForeground=true` |
| 回归：撤销通知权限后开启 MCP | 仍弹出「开启 MCP 前需要授权」，列表只有「允许通知」，确认后台运行已不在必需项中 |
| 设置页入口 | MCP 连接页显示「后台运行（可选）· 未允许 · 可能被系统中断」 |

## 备注

- 模拟器为 userdebug 镜像，`/system/xbin/su` 权限为 `root:shell 6755`，普通应用无法执行，因此 Root 后端在此环境不可用；验收使用 Shizuku 后端完成。真机（KernelSU）上的 Root 路径不受影响。
- 原 `docs/MCP_HOME_VALIDATION.md` 描述的三秒倒计时提醒已由本次的可选提示替代。
